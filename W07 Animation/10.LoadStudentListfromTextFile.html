Reading a list of students
with text fields

Each student has an ID, a name, an age and an address. The names and addresses contain spaces, so they are read with getline. That needs care, and it is where most bugs in this program come from.

Common mistakes newbies make

1. Using one getline for the name

The first getline only reads the leftover newline, so the name stays empty and every later field shifts. Keep both calls, or call f.ignore() after >> instead.

2. Reading the name with >>

f >> st.name stops at the first space, so Nguyen Van An becomes Nguyen. Use getline for text with spaces.

3. Deleting a getline

Removing either getline in a pair shifts every field after it by one line. The name ends up in the age and the address in the next student's id.

4. Uncommenting the strip line on the wrong file

st.name[strlen(st.name) - 1] = '\0'; removes the last character. It is only needed if the file has Windows line endings (a stray \r). On a clean file it deletes a real letter. Also add #include <cstring> before using strlen.

5. Text longer than 100 characters

getline stops at 100 characters, and the rest of the line is read as the next field. Everything after it is then out of sync. Keep each name and address under 100 characters.

6. Fields in a different order

If the file lists age before name, the program still reads it without error, but each value goes into the wrong field. The file layout must match the order in loadStudent.

Tip: if a field looks wrong, print each field right after loading it to find which read went out of step.

Common mistakes newbies make

1. One stream for two files

Declaring ifstream f; and using it for both paths. The second open() fails unless the first is closed. Fix: separate f1 and f2.

2. Missing & in loadFraction

Fraction p changes a copy, so a stays unset. Also, ifstream f without & does not compile, because streams cannot be copied.

3. Single backslash in the path

"D:\fraction1-input.txt" contains \f, a form-feed escape, so the name breaks. Fix: "D:\\fraction1-input.txt".

4. Reading after a failed open

If a file did not open, the else branch is skipped in this code. But if the check is removed, >> fails silently and a and b keep garbage values.

5. Swapping the streams

loadFraction(f2, a) puts 5/6 into a even though the input came from the other file. Match f1 with a and f2 with b.

6. Assuming >> always works

If the file has letters or too few numbers, the stream enters a fail state and the variables keep old values, with no error shown. Check the stream if the input is not guaranteed.

Tip: if the output looks wrong, print the values right after each loadFraction call to find where it goes wrong.

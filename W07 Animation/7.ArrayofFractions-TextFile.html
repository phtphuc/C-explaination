STEP 1

Problem & example

Requirements

  • Read n from the keyboard, then n fractions, each with a numerator num and a denominator denom.
  • Save to D:\fractionarray-output.txt: first line n, then one fraction per line as num denom.
  • If the file cannot be created, print Can not create file.
The array a[100] has room for 100 fractions, but only the first n are used.

inputFractionArrayFraction a[], int &nRead n, then call inputFraction for each a[i]
saveFractionArrayofstream &f, Fraction a[], int nWrite n, then call saveFraction for each a[i]

int &n

Reference: the n read inside the function is the same variable as n in main.

Fraction a[]

Passed as a pointer to a[0], so the array itself is filled, not copied.

Fraction p (by value)

saveFraction only reads p, so it gets a copy. The array is not changed.

Normal run

Read n and n fractions, write n and the fractions, close the file.

File cannot be created

is_open() is false: the if branch prints Can not create file. Nothing is written and nothing needs closing.

n larger than 100

The array only has 100 slots. Writing beyond a[99] is undefined behaviour.

SUMMARY

Notes & summary

Fixed array size

n is not checked against 100. Input more than 100 fractions and the loop writes past the array.

No input check

Typing letters instead of numbers breaks cin. Check cin.fail() after reading.

Zero denominator

Nothing stops denom = 0. Check it before using the fraction later.

Windows path

Drive D: exists on Windows only. Elsewhere is_open() returns false.

Reference &n

Lets the input function set n in main.

Array a[]

Passed as a pointer, so the values are filled in place.

Value p

saveFraction gets a copy and only reads it.

One file, many calls

Pass the ofstream by reference so every write goes to the same file.

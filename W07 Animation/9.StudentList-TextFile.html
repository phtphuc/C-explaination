STEP 1

Problem & example

Requirements

  • Read n students. Each has an id, a name (may contain spaces), an age and an address.
  • Save to D:\studentarray-output.txt: first line n, then each student as four lines: id, name, age, address.
  • If the file cannot be created, print Can not create file.
A name or address can hold up to 100 characters. char name[101] reserves one extra slot for the end-of-string marker '\0'.

Keyboard buffer

▸ (empty)

↵ = newline (the Enter key). It is left in the buffer after cin >> and must be consumed before the next text read.

Fix in practice: call cin.ignore() after each cin >>, then use one getline. The two-getline version here works only when the user presses Enter right after each number.

Normal run

Read n students, write n and each student's four fields, close the file.

File cannot be created

is_open() is false: the if branch prints Can not create file. Nothing is written.

Input longer than 100 characters

getline stops at 100 characters and sets the fail state. The rest stays in the buffer, and later reads go wrong.

SUMMARY

Notes & summary

Mixing cin >> and getline

cin >> leaves a newline behind. A getline right after reads it as an empty line.

Fixed array size

n is not checked against 100. More than 100 students writes past the array.

Input length

Name and address are limited to 100 characters. Longer input breaks later reads.

Copying large structs

Passing Student by value copies 202 characters for every call. const Student &st avoids the copy.

Reference

Student &st lets inputStudent fill the array element.

getline

Reads a whole line, so names with spaces work.

One field per line

The file is easy to read back in the same order.

Same file, many calls

Pass ofstream by reference so every write goes to one file.
